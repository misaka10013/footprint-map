# 我的足迹地图 · footprint-map

> 一张属于你自己的地图。去过的地方、想吃的美食、想去的远方，双击地图就能记一笔。
> 纯静态网页，**双击 HTML 就能用，上传到服务器也能用，数据全在你自己手里**。

在线体验：<[御坂博客足迹](https://misaka10013.cn/map/)> 

<[work Buddy托管版本](https://misaka10013.cn/map/)> 可快速部署或者让workbuddy修改代码。

---

## 它解决什么问题

很久前，我就想在自己博客加一个个人地图，用来记录「去过哪」，不要哪些导航软件的花里胡哨功能和广告。做一个单纯的地图收藏夹，而且我特别喜欢卫星地图，能看到地面的细节，想起往事，记录往事。

这个项目就是实现这点。

- 点位可以是「去过的」，也可以是「想去的」——同一个地图上，看的是人生轨迹 + 愿望清单
- 每个点位能写 Markdown：路书、票价、住宿、照片（外链图床）
- 想去的地方可以先标成「未去过」，去过之后改成「已去过」并填时间，轨迹会自动连线
- 全部数据一键导出成 JSON，换设备、换电脑、甚至换掉这个项目本身，数据都跟着你走

## 三种用法，同一份代码

打开页面右下角的 **⚙️ 设置** 就能切换，页面会记住你的选择。

| 模式 | 适合谁 | 数据存在哪 | 需要联网吗 |
|---|---|---|---|
| **本机** | 自己一个人用，不想折腾 | 浏览器本地存储（localStorage） | 只有加载底图瓦片需要 |
| **静态托管** | 放到服务器上给自己的朋友用 | 每个访客各自的浏览器 | 是 |
| **云端同步** | 手机电脑平板共用一个地图 | 你自己的接口（自带 API 契约） | 是 |

### 用法一：双击打开（最省事）

```
下载整个文件夹 → 双击 index.html
```

没有服务器、没有构建步骤、没有 npm install。`file://` 下也照常工作：
数据写进浏览器本地存储，刷新不丢，关掉再开还在。

> 想换台电脑？点点「💾 导出」得到一个 JSON，带到新电脑上「📂 导入」就行。

### 用法二：扔到任意静态托管

把整个目录上传到 GitHub Pages / Cloudflare Pages / 对象存储 / 自己的 Nginx，
访问 `https://你的域名/index.html` 即可。**不需要 Node、不需要数据库、不需要后端**。

访客打开看到的是示例数据，他自己加的点只存他自己的浏览器 —— 不会串到你的数据里。

### 用法三：接自己的云端（可选）

如果你想让手机和电脑看到同一份数据，可以在设置里填一个 API 地址。
接口契约很小，两个端点：

```
GET  /map/list                                → { ok, exists, rev, items[], priv[], categories, config, privCount }
POST /map/ops   { rev, ops[], kdf }           → { ok, rev }
```

- `ops` 是增量变更日志，不是整份覆盖（`pub` / `pubdel` / `priv` / `privdel` / `meta` 五类）
- `rev` 是乐观锁版本号，两边同时改会返回 `409 REV_MISMATCH`，前端提示先重置再改
- 需要登录的接口，用 `POST /auth/login` 换 token，之后带 `Authorization: Bearer <token>`

这样一个契约同时支撑了「多人只读浏览」和「只有自己能写」两种权限，
实现可以参考 `vendor/auth.js`（100 行的 fetch 封装，无依赖）。

## 功能

**记录**
- PC 双击地图 / 手机长按 600ms 添加点位
- 直接拖动标记调整位置，自动保存
- 六个分类：路程 / 好吃的 / 好喝的 / 好玩的 / 风景 / 兴趣点
- 每个点位支持 Markdown（标题、列表、引用、图片、链接）

**看**
- 六种底图：高德标准、高德卫星、天地图卫星、Esri 卫星、OSM、Carto 浅色
  （天地图需要填你自己的 tk，见下方「底图与 key」）
- **坐标系自动对齐**：数据以 GCJ-02 存储，切到 WGS-84 底图（OSM / Esri / Carto / 天地图）时
  自动反算，点位不会飘几百米 —— 这是国内地图应用最容易翻车的地方
- 路线模式：按时间顺序把所有「已去过」的路程点连成一条线
- 分类筛选 + 时间区间筛选（全部 / 近 1 年 / 近 3 年 / 自定义），两者是「且」关系
- 名称搜索，回车跳转

**数据**
- 导出 / 导入 JSON，导入是**按 id 合并**（撞车自动重新编号，绝不静默覆盖）
- 「清空为空白」和「恢复示例数据」两个一键操作
- 私密点位：标记为私密的点默认不显示，要口令才看得到

## 底图与 key

底图瓦片全部来自公共服务，本项目**不内置任何私有 key**（源码是公开的，内置 key 等于把配额送人）。

| 底图 | 需要 key | 说明 |
|---|---|---|
| 高德标准 / 高德卫星 | 否 | 直接引用瓦片地址，**仅适合个人学习自用**；对公众提供服务请自行申请授权 |
| Esri 卫星 / OSM / Carto | 否 | 按其各自条款署名即可 |
| **天地图卫星** | **是** | 到 <https://console.tianditu.gov.cn/api/key> 免费申请，粘进「设置 → 底图 · 天地图 key」 |

没填 key 时，切到天地图会被拦下并提示；填过之后自动生效，无需改代码。

## 关于私密点位（说清楚它到底保护什么）

这是本项目最容易误解的地方，所以单独说：

| 模式 | 私密的含义 | 强度 |
|---|---|---|
| 本机 / 静态托管 | 界面上隐藏，**数据在浏览器里是明文** | 只防「别人拿你电脑随便点」，不防技术手段 |
| 云端同步 | 每条点位单独 AES-256-GCM 加密，密文才落盘 | 真加密，密钥由口令经 PBKDF2-SHA256（60 万次）派生 |

为什么本机模式不做加密：`file://` 下的浏览器不提供 WebCrypto（不是安全上下文），
做不了真正的密码学操作。与其搞一个看着像加密、实际上只是混淆的东西骗人，
不如直说「这是隐藏，不是加密」，让用户自己判断该不该放敏感内容。

云端模式的加密是真做的，而且有三条硬边界：

1. 未登录时服务端**不下发**密文（不是前端隐藏，是根本拿不到）
2. 静态文件里**没有**任何密文（否则攻击者直接下载文件离线爆破）
3. 密钥只存在内存和 `sessionStorage`，关掉标签页就失效，永不落 `localStorage`

## 数据格式

导出的 JSON 就是完整的数据源，可以直接手改再导入：

```json
{
  "config": {
    "defaultCenter": [30.533, 105.573],
    "defaultZoom": 11,
    "defaultLayer": "satellite",
    "title": "我的足迹地图"
  },
  "categories": [
    { "key": "journey", "name": "路程", "icon": "red-dot", "inRoute": true }
  ],
  "markers": [
    {
      "id": "m_1718457600000_a3f2",
      "lat": 30.657,
      "lng": 104.066,
      "name": "成都春熙路",
      "category": "journey",
      "visited": true,
      "time": "2024-06-15 14:30",
      "content": "## 记录\n第一次来成都。"
    }
  ]
}
```

| 字段 | 说明 |
|---|---|
| `lat` / `lng` | 以 **GCJ-02**（火星坐标）存储，换底图时前端自动换算 |
| `name` | 地点名称，必填 |
| `category` | 必须是 categories 里的 key |
| `visited` | 是否去过；`journey` 用它决定要不要连进路线 |
| `time` | `YYYY-MM-DD HH:mm`，只对已去过的点有意义 |
| `content` | Markdown 正文，图片走外链 |
| `poi` | `true` 表示这是公共景点，不参与时间筛选 |
| `isPrivate` | 私密点位（云端模式下只存在于解密后的内存里） |

改 `seed.js` 里的 `window.__FP_SEED__` 就能换掉所有人首次打开看到的示例数据。

## 技术栈

**零构建、零 npm、零框架**。

| 组成 | 体量 | 作用 |
|---|---|---|
| `index.html` | 10 KB | 结构 |
| `app.js` | 118 KB | 业务逻辑：渲染、筛选、表单、路线、坐标转换 |
| `config.js` | 10 KB | 运行模式判定、本机存储、口令指纹 |
| `seed.js` | 12 KB | 示例数据 |
| `style.css` | 44 KB | 样式（含内联的 Leaflet 基础样式） |
| `vendor/leaflet.js` | 144 KB | 地图引擎 |
| `vendor/marked.js` | 35 KB | Markdown 渲染 |

依赖全部内联在 `vendor/`，**不请求任何 CDN** —— 断网、内网、飞机上都能打开
（只有底图瓦片需要网络）。

## 已知限制

1. **底图瓦片来自第三方服务**（高德 / 天地图 / Esri / OSM / Carto）。自己用没问题，
   如果要做成对公众开放的服务，请先确认各家条款与署名要求，或者换成自建瓦片。
   天地图必须填自己的 key，天地图不对「一个 key 全站公用」提供授权。
2. **单机容量受浏览器限制**：localStorage 一般 5 MB 左右，纯文字点位能存几千条。
   图片请用外链图床，不要塞 base64 进 `content`。
3. **本机模式不跨设备**：换电脑要手动导出导入。想要自动同步请用云端模式。
4. **搜索只匹配点位名称**，不做地名解析（那需要接地理编码 API，会引入依赖和配额问题）。
5. **示例数据的坐标来自公开景点信息**，个别景区在 OSM 里只有保护区边界，
   落点会比实际景偏几公里 —— 直接拖动标记就能修正，改完自动保存。
